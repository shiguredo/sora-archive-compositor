## 目的

残っている open issue を、影響範囲の小さいものから順に片付ける。作業ブランチとレビューの単位を壊さないため、実装は常に子 issue 側で行い、本 issue は推奨順の台帳として使う。

順不同で着手すると、公開前の掃除とパイプライン横断バグが同時に走り、レビューと revert の単位が壊れる。

## 設計方針

- 1 issue = 1 ブランチ。本 issue のブランチでは子 issue のコード変更をしない
- 着手前に対象 issue を polish する。未 polish のまま実装しない
- 依存があるものは先に依存元を閉じる

### 本 issue でやらないこと

- 子 issue の実装・polish・closed への移動（最終順の実行は各子 issue 側）
- 新しいバグやリファクタの起票 (見つかったら別 issue にする)

## 完了条件

- 軽い掃除枠を消化し、残 open の着手順を台帳に固定した
- 以降の作業は各子 issue を個別に進める（本台帳の更新は不要）

## 解決方法

台帳としての役割を終え、closed にした。

- 軽い掃除（0007〜0009）は消化済み
- 残作業の順を `0006 → 0004 → 0005 → 0002` に固定した
- リリース関連（0001 / 0003 / 0010）はリリース直前まで後回しと明記した
- 子 issue がすべて closed になる前でも、推奨順の決定と軽い掃除の消化で本 issue の目的は達したため、以降は各子 issue を個別に進める
