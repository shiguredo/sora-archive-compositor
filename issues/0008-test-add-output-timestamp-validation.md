# e2e テストに出力 MP4 のトラック内タイムスタンプ整合を追加する

- Created: 2026-08-04
- Completed: {YYYY-MM-DD}
- Branch: feature/test-add-output-timestamp-validation
- Polished: 2026-08-28

## 目的

`tests/e2e.rs` に、出力 MP4 を読み直したときの **トラック内** タイムスタンプ整合（0 基点・単調増加・想定グリッド）を検証するアサートを追加する。現状はトラック尺の合計しか見ておらず、stts の並びが崩れていても検出できない。

## 現状

`tests/e2e.rs` が検証しているのは主に (a) サンプル数、(b) トラック尺の合計、(c) コーデック・解像度、(d) デコード後のピクセル値。サンプル列の `timestamp` / `duration` は見ていない。

- トラック尺の合計が合っていても、duration が 2 倍でサンプル数半分のような不正な stts は検出できない
- 音声の出力グリッドは `mixer_audio::MIXED_AUDIO_DATA_DURATION`（20ms）固定。映像はレイアウトの `frame_rate`（既定 `FPS_25` なら 40ms）に依存する。既存フィクスチャでは音声トラック尺 1020ms・映像 1000ms であり、**A/V の終端時刻は一致しない**（これが現行の正常出力）
- trim を含む compose の E2E は無く、trim は `tests/layout_test.rs` や mixer 系ユニットテストに留まる
- `simple_split_archive` のオフセットは 0–1 / 1–2 / 2–3 の連続のみ。非連続オフセットの分割フィクスチャは無い

### 関連する決定（誤解しやすい点）

- 音声は入力タイムスタンプのギャップを詰め、映像側に穴埋めしない。ギャップ時の A/V 尺ズレは意図どおりでコード変更しない
- 0011: 「ギャップ詰め前提の同期検証は不要」。本 issue でギャップ付き入力に対して A/V 終端一致を要求してはならない
- 映像の大きなタイムスタンプギャップでは hold / duration 延長（必要なら分割）が起き、**全サンプルが固定グリッドとは限らない**

## 設計方針

検証の読み取り手段は既存の `Mp4AudioReader` / `Mp4VideoReader`（`timestamp` / `duration`）を使う。

### 必須: 連続入力（ギャップ延長が起きない）ケースのトラック内整合

既存の単純 compose E2E（例: `test_simple_single_source_common` 相当）に、各トラックについて次を追加する。

- 先頭サンプルの `timestamp` が 0
- 各サンプルについて `timestamp(n+1) == timestamp(n) + duration(n)`（単調・連続）
- 音声: 各 `duration` が `MIXED_AUDIO_DATA_DURATION`（20ms）
- 映像: 各 `duration` が当該レイアウトのフレーム間隔（既定 25fps なら 40ms）。`frame_rate` を変えるケースを足す場合は、その fps に合わせる
- A/V の終端時刻一致はアサートしない（既存期待値 1020ms / 1000ms を維持）

### 任意だが本 issue に含めてよい: trim の E2E

- trim 付き layout で compose し、出力尺・サンプル列が trim 後の期待に沿うことを E2E で確認する
- 期待値（開始・終了・サンプル数）を本文実装時にフィクスチャから固定する

### 本 issue でやらないこと

- 「音声・映像の最終サンプル時刻が一致する」ことの検証（ギャップ有無を問わず）
- ギャップ付き入力で A/V 同期を強制するテスト（ギャップ詰め方針および 0011 と衝突する）
- ギャップ延長・分割そのものの再検証（mixer / writer の既存テストがある）。必要ならトラック内の単調性だけに留める

ギャップ付き分割フィクスチャが欲しくなった場合は、別 issue で「意図どおりの A/V 尺差・トラック内契約」を固定する（本 issue の完了条件には含めない）。

## 完了条件

- 連続入力の compose E2E で、音声・映像それぞれのサンプル列が 0 基点・連続・想定 duration グリッドであることが検証されている
- A/V 終端一致を要求するアサートを入れてない
- （含める場合）trim 付き compose の E2E がある
- `cargo test --workspace` が全 pass する
